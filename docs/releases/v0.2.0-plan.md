# PhotonAct v0.2.0 plan

Status: implemented in v0.2.0. This document records the original scope and acceptance criteria;
the release summary is in [v0.2.0.md](v0.2.0.md).

## Goal

Let a user prepare a legitimately held optical response curve locally, inspect its provenance and
validity, and evaluate the same curve with explicitly configured, reproducible hardware effects in
PyTorch. The default behavior remains the v0.1 curve or hysteresis activation.

## 1. Local curve preparation

- Add a generic `photonact prepare` command for CSV and, with the `data` extra, XLSX input. Support
  both a single branch column and separate up/down input-output column pairs, as in the private
  Figure 4(b) workbook. The caller explicitly chooses the sheet and columns, physical units,
  source, data kind, license, and optional wavelength, polarization, and thresholds. A named,
  explicit `input * transmittance` transformation may generate output power when that is what the
  source columns represent; preserve the original transmittance column.
- Preserve the source file. Write canonical CSV plus `.meta.json` into a caller-selected local
  directory, and include the source SHA-256 and conversion settings in a machine-readable report.
- Reject missing or non-finite values, duplicate input values within a branch, incompatible branch
  ranges for hysteresis, and incomplete threshold metadata with row-level diagnostics. Sorting must
  be an explicit option; smoothing, resampling, implicit unit conversion, and threshold inference
  are outside v0.2.0.
- Extend `photonact inspect` to summarize provenance, units, branch coverage, threshold locations,
  and validation warnings. Keep `local_data/` ignored by Git.

## 2. Opt-in hardware effects

Introduce a small, serializable effect configuration that can wrap `CurveActivation` and
`HysteresisActivation`. Defaults are disabled and preserve current forward outputs and gradients.

The documented evaluation order is: input drift -> state transition and curve interpolation ->
output-side insertion loss -> output range limit -> output quantization -> readout noise. Input
drift uses the curve's input unit; the other parameters use the output unit, except insertion loss,
which is specified in dB and converted to a power ratio. The applied input after drift determines
the hysteresis transition. No effect is claimed to be calibrated to a physical device by default.

- **Drift:** explicit additive input offset; a time-varying drift model requires user-supplied
  parameters and is deferred.
- **Insertion loss:** non-negative dB attenuation of output power, with an explicit limitation for
  curves whose response quantity is not power.
- **Finite range:** configured lower/upper output bounds; out-of-range values are clamped.
- **Quantization:** configured positive output step and rounding rule. Exact rounding has a zero
  gradient almost everywhere; an optional straight-through surrogate must be labeled as such.
- **Noise:** zero-mean Gaussian readout noise with explicit standard deviation and caller-owned
  seeded random generator. The stochastic sample and gradient convention are documented.

## 3. User-facing example and release gates

- A synthetic, redistributable example shows baseline, each effect independently, and a combined
  configuration. It prints its settings and seed and can regenerate the same results.
- Unit tests cover effect order, units and invalid parameters, threshold behavior after drift,
  seeded reproducibility, exact no-effect equivalence, gradients, CPU serialization, and batched
  trajectories. Run the existing Python 3.10-3.12 CI matrix and installed-wheel smoke test.
- Document the exact API, model assumptions, input/output units, privacy boundary, and migration
  notes in English and Chinese. Tag v0.2.0 only after the synthetic example and local private-curve
  smoke test both pass.

## Boundaries

Do not publish the paper's source workbooks, derived curve, or generated HTML without the data
rights being resolved. The release must not claim to reproduce paper accuracy or model effects not
supported by measurements. MNIST/Fashion-MNIST comparisons remain in v0.3.
